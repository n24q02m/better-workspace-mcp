## 2025-02-27 - Cache Google OAuth Client Instance
**Learning:** The WorkspaceAuth class was reading credentials from disk (via `this.store.load()`) and instantiating a new `google.auth.OAuth2` client every single time `getAuthenticatedClient()` was called. Because this is called on every tool invocation in the MCP server, it introduced unnecessary disk I/O and object creation overhead per tool call, creating a minor performance bottleneck.
**Action:** Implemented instance-level caching of the OAuth client in the `WorkspaceAuth` singleton. Next time, always check if singletons or heavily reused managers are doing disk I/O on every access, and consider caching the resulting objects in memory.
## 2025-02-27 - Rejected OAuth Client Caching
**Learning:** An optimization that caches the `OAuth2Client` was rejected because the 0.43ms win per call is negligible compared to 100-1000ms API round trips, making it a micro-optimization not worth the complexity. Furthermore, adding an unkeyed cache to a singleton (`WorkspaceAuth`) creates a cross-account credential leak risk for the upcoming M2 (multi-account) milestone. Finally, formatting changes unrelated to the optimization were flagged as scope creep.
**Action:** 1) Measure optimizations in the context of the total operation time (don't optimize sub-millisecond paths when network calls take 100x longer). 2) Never introduce unkeyed state into singletons if the system is moving towards multi-tenancy. 3) Strictly avoid unrelated formatting changes (scope creep) in PRs.
