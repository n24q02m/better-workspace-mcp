🚨 Severity: HIGH
💡 Vulnerability: The OAuth consent callback handler in `src/auth/add-account-remote.ts` was previously returning raw unhandled exception strings (like `err.message` which can contain traces) back to the user interface on 500 status codes.
🎯 Impact: This caused an information leakage vulnerability because it could potentially send backend stack traces or internal server error states directly to a client, which violates the principle of failing securely.
🔧 Fix: We now log the detailed original error to `console.error` internally for our records, but return a safe, generic message (`An internal error occurred. Start again with <code>config(action="account_add")</code>.`) to the client, effectively masking internal specifics.
✅ Verification: Ran `bun run build && bun run check && bun run test` successfully; all 404 test assertions correctly passed, ensuring functionality operates seamlessly. Added finding to `.jules/sentinel.md`.
